# Quy trình phát hành

- `main` là bản Production; các nhánh kết nối khác như `develop`, `feature/*` và `release/*` tạo deployment Preview. Không promote Preview thành Production.
- Push/PR lên `main`, `develop`, `feature/**` hoặc `release/**` chạy GitHub Actions: cài dependency bằng lockfile, typecheck, lint, unit tests, production dependency audit và build. Vercel Git Integration tự triển khai nhánh không phải `main` thành Preview và `main` thành Production.
- Chỉ merge commit đã qua CI; release dùng merge commit trên `main`, giữ nguyên `develop` cho công việc tiếp theo. Không force-push các nhánh dùng chung. Tạo nhánh `feature/*` từ `develop`; nếu cần làm song song, dùng `git worktree` riêng cho mỗi nhánh và dọn worktree sau khi merge.
- Giữ `package-lock.json` đồng bộ; tăng `package.json` theo Semantic Versioning khi phát hành mốc tính năng/bản vá. Tạo tag `vMAJOR.MINOR.PATCH` cho bản phát hành đã xác nhận.
- Khi build chạy trong `VERCEL_ENV=preview`, `npm run vercel-build` chỉ áp migration sau khi `PREVIEW_DATABASE_URL` dùng domain Neon, endpoint/database khớp `PREVIEW_DATABASE_ENDPOINT_ID`/`PREVIEW_DATABASE_NAME`, và Neon project ID khớp chính xác `PREVIEW_DATABASE_PROJECT_ID`. Thiếu hoặc không khớp thì migration dừng. Preview runtime và migration đều ưu tiên biến riêng này, không lấy URL từ Neon integration.
- Preview phải có Secret `PREVIEW_DATABASE_URL` riêng, scope theo nhánh Git UAT đã chọn; không sao chép URL Production vào Preview. Nếu chưa cấu hình nhánh riêng, CI GitHub vẫn kiểm tra code nhưng Vercel Preview sẽ dừng có chủ đích. Trước UAT vẫn phải xác minh endpoint của deployment khớp nhánh UAT.
- Trước migration/UAT, đối chiếu chính xác Neon branch của deployment trong Neon Console (cột deployment/branch hoặc URL deployment được tiêm). `vercel env pull/run --environment preview` chỉ lấy biến Preview cấp project; không chứng minh đó là Neon branch riêng của một deployment. Không dùng branch `main` hay dữ liệu Production làm UAT.
- Không chụp màn hình, ghi log hoặc dán connection string/DB password vào chat, issue hay source control. Chỉ chuyển credential bằng secret field hoặc integration chính thức, giới hạn ở Preview. Nếu giá trị đã bị hiển thị ngoài nơi lưu bí mật, dừng sử dụng, xoay credential theo đúng phạm vi rồi mới cấu hình lại; xác minh host/branch từ metadata không nhạy cảm trước dry-run.
- Với release candidate hiện tại, build Production chỉ build app; migration Production được chạy riêng bằng lệnh có cờ `--production` sau khi các cổng release đạt. Không chạy migration từ nhánh `develop` trên cơ sở dữ liệu Production.
- Không chạy migration dry-run trên Production. Chạy dry-run chỉ trên Neon Preview/UAT đã được xác minh là cô lập; đối chiếu file migration còn chờ với kế hoạch release trước khi chạm Production.
- Production migration phải là bước tường minh sau khi các cổng release, backup/PITR và rollback đã đạt: `vercel env run -e production -- npm run db:migrate:production`. Lệnh dùng biến Production tạm thời trong tiến trình, không xuất `.env` ra file; cờ `--production` kích hoạt kiểm tra `PRODUCTION_DATABASE_ENDPOINT_ID` và `PRODUCTION_DATABASE_NAME`. Script từ chối dry-run trong Production. Cú pháp `vercel env run -e production -- <command>` theo [tài liệu Vercel CLI](https://vercel.com/docs/cli/env).
- Build Production chỉ build app; không kết nối DB, kiểm tra URL DB hay tự áp migration. Endpoint Production được kiểm tra ngay trong lệnh migration tường minh. Khi migration đã được duyệt và chạy riêng, triển khai code sau đó; kiểm tra `/api/health`, deployment log và một luồng nghiệp vụ read-only.
- Cổng Production bắt buộc: chủ sở hữu nghiệp vụ thống nhất riêng RPO (mức mất dữ liệu tối đa) và RTO (thời gian khôi phục tối đa); đối chiếu chúng với thời hạn PITR thực tế, giới hạn dung lượng thay đổi, lịch snapshot và chi phí của gói Neon. Thời hạn PITR không tự nó xác định RPO. Diễn tập restore vào branch riêng không ghi lên branch nguồn; xác định deployment Ready để rollback và rà soát thao tác rollback trước cửa sổ phát hành. Không đổi database, alias Production, hoặc `main` khi các cổng này chưa đạt.
- `BETTER_AUTH_SECRET` Preview là một secret riêng, không dùng chung với Production.
- Mỗi môi trường dùng VAPID key pair riêng. Không chép private key Preview sang Production; xác nhận đăng ký/gửi/nhận Push trên Android thật trước khi coi push đã nghiệm thu.
- TWA/APK chỉ phát hành sau khi chốt `applicationId`, signing owner và quy trình backup keystore; `/.well-known/assetlinks.json` phải khớp package name cùng SHA-256 fingerprint của chứng thư đang ký.
- Mỗi thay đổi nghiệp vụ cần kiểm tra local UAT, lint, typecheck, unit test và production build trước khi merge.
- Duy trì `main` như điểm rollback qua deployment Ready gần nhất; nếu release lỗi, rollback Vercel trước, không tự ý sửa/xóa dữ liệu để “khớp” code. Database migrations phải theo hướng tương thích ngược và additive; migration destructive cần kế hoạch backup/restore riêng.

### Rollback GD1 auth/platform owner/legacy review

- Code rollback: chọn deployment Production `READY` ngay trước release; kiểm tra lại deployment ID/alias tại thời điểm phát hành. Tại lần rà 06/11/2026, hiện tại là `6037661`; deployment `READY` liền trước là `c2c148f` (`kdbt-app-dat-hang-gtukpy6ds-vohanh19902026-droid.vercel.app`). Đây là mốc tham chiếu, không thay cho việc xác nhận lại trước release.
- Migration runner áp mỗi file trong transaction riêng và ghi tên vào `_app_migrations`. Khi một file lỗi, transaction của file đó rollback; các file trước đã commit vẫn còn. Không chạy lặp hoặc xóa migration ledger để ép áp lại.
- `0010_notification_preferences_and_push.sql`: thêm preference mặc định và bảng push; giữ schema khi rollback code vì có thể đã phát sinh dữ liệu subscription.
- `0011_fix_default_sand_catalog_typo.sql`: sửa JSON danh mục đã lưu; không có down migration an toàn vì không lưu before-image. Nếu có sai lệch, xác minh giá trị hiện tại rồi tạo forward-fix; không đảo hàng loạt về `Cát Lọc`.
- `0012_google_registration_approval.sql`: thêm trường hồ sơ; giữ khi rollback code để tránh xóa dữ liệu đăng ký.
- `0013_platform_owner.sql`: thêm cờ owner và unique partial index; giữ khi rollback code để không xóa trạng thái owner.
- `0014_legacy_concrete_review.sql`: thêm các bảng review riêng; giữ bảng/dữ liệu nếu đã có import được duyệt. Không drop như một bước rollback tự động.
- Không có script down cho các migration trên. Nếu cần khôi phục dữ liệu, tạo branch restore riêng từ PITR/snapshot đã xác nhận, kiểm tra trên branch đó rồi mới lập kế hoạch cutover riêng; tuyệt đối không restore thử hoặc ghi đè Neon Production.

## Hạ tầng hiện tại và các lựa chọn

- PostgreSQL/Neon là nguồn dữ liệu chuẩn. Chưa cần Redis: hiện không có hàng đợi, cache chia sẻ hoặc trạng thái realtime cần Redis. Bộ giới hạn đăng nhập còn lưu trong RAM từng Vercel instance nên chỉ phù hợp lưu lượng nhỏ; trước khi mở SaaS hoặc tăng tải cần thay bằng rate limit dùng chung và đo tải thực tế.
- GitHub Actions chạy quality gate; Vercel Git Integration lo Preview/Production deployment. Không thêm một pipeline deploy thứ hai để tránh hai lần build/đẩy song song.
- `npm run db:migrate:dry` chỉ kết nối đọc trạng thái migration để in danh sách dự kiến; không thay đổi schema.
- Load test deployment Preview phải dùng phương thức truy cập được duyệt, wrapper `scripts/load-test-preview.ps1` và chỉ nhắm deployment `READY` có target `preview` đã được Vercel CLI xác nhận thuộc project liên kết. Harness chỉ gọi GET read-only `/api/health`, xác thực JSON khỏe và chặn hostname Production đã biết. Không tắt Deployment Protection, phát hành share link công khai hoặc trích cookie từ trình duyệt.
- Nếu Preview parent có dữ liệu chưa được xác minh/mask, không dùng auto-branching từ parent đó cho UAT. Tạo schema-only branch hoặc database Preview sạch, seed dữ liệu tổng hợp, rồi xác nhận deployment thực sự dùng branch sạch trước khi ghi dữ liệu kiểm thử.
